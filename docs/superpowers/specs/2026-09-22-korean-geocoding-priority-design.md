# 한국어·국내 주소 검색 우선 설계

## 배경

현재 Photon 검색 요청에 언어와 위치 기준이 없어 브라우저에서는 영어 이름이 먼저 표시되고, `태평동 7184-9`처럼 국내 지번을 검색해도 해외의 유사 숫자 주소가 우선 노출된다.

## 결정

기존 정적 웹 앱 구조와 Photon을 유지하면서 다음 검색 파라미터를 적용한다.

- `lang=default`: OSM 객체의 지역 기본 이름을 사용해 한국에서는 한국어 이름을 우선 표시한다.
- `lat`, `lon`: 앱의 `DEFAULT_CENTER`를 검색 위치 편향으로 전달해 성남·서울권 결과를 우선한다.
- `limit=5`: 기존 결과 개수를 유지한다.

대한민국 `bbox`로 결과를 강제 제한하지 않는다. 국내 결과를 우선하되 사용자가 해외 장소를 명시적으로 검색할 가능성은 유지한다. 역지오코딩에도 `lang=default`를 적용해 지도에서 선택한 지점의 지역 기본 이름을 표시한다.

## 데이터 흐름

1. 사용자가 주소나 장소명을 입력한다.
2. `searchPlaces`가 검색어, 결과 제한, 지역 기본 언어, 기본 지도 중심 좌표를 Photon에 전달한다.
3. Photon 결과는 기존과 동일하게 `{ label, lat, lng }`로 정규화한다.
4. 지도 클릭 역지오코딩은 지역 기본 언어로 라벨을 요청한다.

## 오류 및 한계

- Photon에 등록되지 않은 상세 건물 주소는 결과가 없을 수 있다.
- 위치 편향은 우선순위 조정이며 대한민국 외 결과를 완전히 차단하지 않는다.
- 검색 실패 시 기존 지도 직접 선택 안내를 유지한다.

## 대안

### Kakao Maps JavaScript SDK

국내 장소명과 상세 주소 검색 품질이 가장 유리하다. GitHub Pages에서도 도메인 제한 JavaScript 키를 사용할 수 있지만 Kakao 계정, 키 관리, 쿼터 및 약관 의존성이 생긴다. 향후 상세 건물 검색이 핵심 요구사항이 되면 우선 검토한다.

### Naver Geocoding API

국내 주소 품질은 좋지만 Client Secret을 브라우저에 노출할 수 없어 일반적으로 백엔드나 서버리스 프록시가 필요하다. 현재의 서버 없는 정적 앱 구조에는 적용하지 않는다.

## 검증

- 검색 URL에 `lang=default`, `lat`, `lon`, `limit=5`가 포함되는지 단위 테스트한다.
- 역지오코딩 URL에 `lang=default`가 포함되는지 단위 테스트한다.
- 실제 Photon 요청에서 `거여역`이 한국어로, `태평동 7184-9`가 성남시 인근 결과로 우선되는지 확인한다.
- 전체 테스트와 Vite 빌드를 실행한 뒤 GitHub Pages를 재배포한다.
