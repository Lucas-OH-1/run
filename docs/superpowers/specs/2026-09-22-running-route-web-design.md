# 러닝 경로 웹 앱 설계

## 목적

출발지와 도착지를 지정하면 자동차 통행로보다 하천변 보행로, 산책로, 녹도를 우선하는 러닝 경로를 제시한다. 한 번 정한 경로만 보여주는 페이지가 아니라 주소 검색, 지도 선택, 현재 위치를 이용해 다른 경로도 조회할 수 있는 재사용형 웹 앱으로 만든다.

## 배포

- GitHub 저장소: `Lucas-OH-1/run`
- GitHub Pages 주소: `https://lucas-oh-1.github.io/run/`
- 정적 웹 앱으로 배포하며 별도 애플리케이션 서버는 두지 않는다.
- 사용자의 위치, 주소 검색 기록, 선택 경로는 서버나 저장소에 저장하지 않는다.

## 기술 구성

- 지도 데이터 및 타일: OpenStreetMap
- 지도 UI: Leaflet
- 주소 검색: Photon
- 경로 계산: BRouter와 앱에 포함된 러닝용 커스텀 프로필
- 배포: GitHub Pages 및 GitHub Actions

모든 외부 서비스는 무료 공개 서비스를 저빈도로 사용하는 개인용 앱을 전제로 한다. OpenStreetMap 저작자 표시와 각 서비스의 사용 정책을 지킨다. 공개 서비스는 가용성이 보장되지 않으므로 요청 실패 시 오류 안내와 재시도를 제공한다.

## 사용자 입력

사용자는 다음 세 방식으로 출발지와 도착지를 지정할 수 있다.

1. 주소 또는 장소명 검색
2. 지도 클릭
3. 브라우저 현재 위치

출발지와 도착지가 모두 지정된 뒤 `러닝 경로 찾기`를 실행한다. 지도 클릭 모드에서는 현재 지정 중인 지점이 출발지인지 도착지인지 화면에 분명히 표시한다.

## 경로 유형

### A. 하천변 보행로 우선

추천 기본값이다. 우선순위는 다음과 같다.

1. 하천변 보행 전용길과 산책로
2. 보행자와 자전거가 분리된 길
3. 보행 가능한 자전거 겸용도로
4. 일반 인도
5. 자동차 도로와 인접한 보행로

계단과 자동차 도로를 강하게 회피한다. OpenStreetMap에 보행로와 자전거도로가 별도 객체로 등록돼 있으면 보행로를 선택한다. 두 길이 하나의 선으로만 등록된 하천 구간에서는 해당 하천변 통로를 유지하고 `자전거도로 옆 보행로 이용` 안내를 표시한다. 보행 금지로 등록된 길은 사용하지 않는다.

### B. 녹도 및 겸용도로 우선

하천변, 공원, 녹도와 보행 가능한 자전거 겸용도로를 적극적으로 사용한다. 짧은 계단은 허용한다. A보다 거리와 연결성을 우선하지만 자동차 도로는 계속 회피한다.

### C. 보행 최단거리

보행 가능한 길 중 거리가 가장 짧은 경로를 제시한다. 큰길 인접 구간이나 계단이 포함될 수 있음을 분명히 표시한다.

## 경로 계산 방식

A와 B는 앱에 포함된 BRouter 커스텀 프로필을 사용한다. A 프로필은 `footway`, `pedestrian`, 보행 가능한 `path`를 가장 낮은 비용으로 평가하고, `cycleway`, 계단, 자동차 도로 순으로 큰 패널티를 부여한다. B 프로필은 보행 가능한 `cycleway`와 짧은 계단의 패널티를 낮춰 연결성과 거리를 개선한다. C는 보행 권한을 지키는 최단거리 프로필을 사용한다.

브라우저는 앱 시작 시 커스텀 프로필을 BRouter에 등록하고 받은 임시 프로필 ID로 경로를 요청한다. 프로필 등록이 만료되거나 실패하면 다시 등록하고 한 번 재시도한다. 경로 응답의 길 분류 정보를 합산해 보행로 비율, 차도 인접 거리, 계단 포함 여부를 계산한다.

## 경로 표시

- A, B, C 경로를 지도에 동시에 표시한다.
- 선택한 경로는 굵고 불투명하게, 나머지는 가늘고 반투명하게 표시한다.
- 각 경로 카드에는 거리, 예상 러닝 시간, 보행로 비율, 차도 인접 거리, 계단 포함 여부를 표시한다.
- 예상 시간은 1km당 6분 30초를 기준으로 한 참고값으로 표시한다.
- 출발·도착 마커와 지도 전체 경로 맞춤 버튼을 제공한다.

## 화면 구성

### 데스크톱

왼쪽 패널에 출발지·도착지 입력과 A/B/C 경로 카드를 배치하고 오른쪽에 지도를 표시한다.

### 모바일

지도를 전체 화면으로 표시하고 검색 및 경로 카드는 화면 하단 패널에 배치한다. 현재 위치 버튼과 전체 경로 보기 버튼은 지도 위에서 엄지손가락으로 누르기 쉬운 위치에 둔다.

## 오류 처리

- 주소 검색 결과가 없으면 검색어를 수정하거나 지도에서 직접 선택하도록 안내한다.
- 현재 위치 권한이 거부되면 주소 검색과 지도 선택을 계속 사용할 수 있게 한다.
- 경로를 찾지 못하면 지점을 도보 연결망에 더 가깝게 다시 선택하도록 안내한다.
- Photon 또는 BRouter 요청 실패 시 서비스 이름을 포함하지 않는 사용자 친화적 오류와 재시도 버튼을 제공한다.
- 네트워크가 끊기면 연결 복구 후 다시 시도하도록 안내한다.

## 데이터 한계와 안전 안내

OpenStreetMap의 길 분류와 실제 현장 상태가 다를 수 있다. 공사, 침수, 야간 폐쇄, 횡단보도 변경을 실시간으로 보장하지 않는다. 하천변 경로, 교량, 지하통로, 자전거 겸용도로에는 현장 확인과 안전 통행 안내를 표시한다.

## 검증

1. 태평동 7184-9에서 위례서로 273 밀파니 타워까지 탄천 보행로 우선 경로를 확인한다.
2. 탄천 구간에서 A가 보행 전용길을 우선하고, 하나의 선으로 등록된 구간에는 보행로 이용 안내가 표시되는지 확인한다.
3. 서로 다른 주소와 지도 클릭 지점으로 재사용 가능한지 확인한다.
4. A, B, C 경로가 모두 표시되고 선택한 경로만 강조되는지 확인한다.
5. 주소 검색 실패, 위치 권한 거부, 경로 API 실패를 확인한다.
6. 데스크톱 Chrome과 모바일 화면 크기에서 레이아웃을 확인한다.
7. GitHub Pages HTTPS 환경에서 현재 위치 기능과 외부 API 요청이 동작하는지 확인한다.
